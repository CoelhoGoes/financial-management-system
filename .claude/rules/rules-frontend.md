# Frontend

`src/` is layered — `presentation/` → `state/` → `data/`, with `shared/` usable by all and
importing none of them. The dependency rule is in `CLAUDE.md` → **Architecture**.

- **`data/api.ts`** — the typed HTTP client. Each method declares its response type from
  `shared/types.ts`, so screens get typed data without casting. On any `401` it clears the stored
  JWT and throws so the caller can redirect to login. Reads `VITE_API_URL`, defaulting to
  `http://localhost:8000`. Token lives in `localStorage` under `gf:token`. It declares
  `Content-Type: application/json` **except** when the body is a `FormData` (the OFX upload in
  `previewImport`): there the browser must set the header itself, because only it knows the
  multipart boundary. Declaring it by hand makes the request arrive unparseable. Error
  messages go through `errorMessage`: a string `detail` is shown as is, and the list a 422
  brings (Pydantic errors, in English) becomes one Portuguese sentence per error, from the
  error `type` and the field's label in `FIELD_LABELS` — a new form field needs its label
  there, or it falls back to a generic sentence. Covered by `api.test.ts`.
- **`state/auth-context.tsx`** — `AuthProvider` wraps the app in `main.tsx` and owns `user`,
  `loading`, `error`. On mount, if a token exists it calls `/auth/me` to rehydrate the session.
  `useAuth()` throws outside the provider. All screens read auth state from here, never from
  `data/api.ts` directly. `updateUser(user)` applies the `UserOut` returned by a `PUT /auth/me`
  (used by `ConfigScreen`) so the provider stays fresh without a second `GET`.
- **`state/theme.ts`** — light/dark/system, saved per device in `localStorage` under
  `gf:theme` (no key = follow `prefers-color-scheme`). The inline script in `index.html` repeats
  the same rule so the `.dark` class is on `<html>` before the first paint — change one, change
  the other. `followSystemTheme()` runs once in `main.tsx`.
- **`shared/api-schema.d.ts`** — generated by `openapi-typescript` from the running API's
  `/openapi.json` (`npm run gen:types`); never edit it by hand. It is versioned so `npm run build`
  and the deploy never need the API up. Nothing regenerates it on its own: `./dev.sh` compares
  it with the API on every start and warns in red when it is stale. The script passes
  `--default-non-nullable false`, otherwise fields with a server default (`method`,
  `installments`) come out required. `openapi-typescript` declares a `typescript ^5` peer; its
  entry in `overrides` (`package.json`) points it at the project's TypeScript 6 (same output,
  verified 25/10/2026).
- **`overrides.deepmerge`** pins `4.1.2`, below the range of GHSA-gcqx-w48m-w2h4, which has no
  fixed version yet. It only reaches the `shadcn` CLI, which asks for `^4.3.1` and only uses
  `arrayMerge`. Remove it when a fixed version ships — tracked in `docs/roadmap.md`.
- **`shared/types.ts`** — short names for the generated types (`Summary`, `EntryOut`…) plus
  `EntryType`/`EntryMethod`, so the rest of `src/` imports from here and never from the
  generated file.
- **`shared/categories.ts`** — `GASTO_CATEGORIES`/`ENTRADA_CATEGORIES`, hand-maintained
  mirror of the closed lists in `docs/dominio.md` — nothing generates it. Keep both in sync,
  don't invent a new category here without updating `docs/dominio.md` too.
- **`shared/format.ts`** — `currentMonth()` (`SummaryScreen`, `EntryScreen`, `InvoiceScreen`),
  `formatCurrency()` (those three plus `ImportScreen` and `TrendChart`), `formatPercent()`
  (`SummaryScreen`), `shiftMonth()` (`MonthNav`, which every month stepper goes
  through), `formatMonthShort()` and `formatCurrencyInteger()` (`TrendChart`, the axis shows whole
  reais) and `formatDayMonth()` (`ImportScreen`, which
  shows a statement line as `21/09` — the year is noise inside one statement). Money and
  percentages go through `Intl.NumberFormat('pt-BR')`, so they read `4.057,30` and `49,4%` —
  never format a number inline in a screen.
- **`presentation/components/`** (outside `ui/`) — `Page` is the shell every authenticated
  screen mounts: `Header` plus a `<main>` capped at `max-w-6xl`; each screen passes its own
  `md:grid` (or a narrower `max-w-3xl`) through `className`, and below `md` everything is one
  column in the phone's order. `Header` is the full-width sticky nav bar: from `md` it fits one
  line and is exactly `--header-height` tall (`index.css`), which the sticky form in
  `EntryScreen` uses as its `top` — anything new in the bar must keep it on one line between
  `md` and `lg` (that is why the email only shows from `lg`). Below `md` the tabs drop to a
  second row, icon only, label kept in `sr-only`. `MonthNav` is the month stepper shared by
  `SummaryScreen`, `EntryScreen` and `InvoiceScreen`, and deliberately does **not** use the
  shadcn `Pagination` — that one renders anchors, since it was built for pages that have a URL,
  and an anchor without `href` breaks keyboard and screen reader. `TrendChart` and
  `CategoryDonut` are lazy-loaded from `SummaryScreen` (`React.lazy` + `Suspense`) so recharts
  stays out of the main bundle. `ChartSwatch` (colour square) and `ChartTooltipRow` ("name … R$
  value") are shared by both charts' tooltips and the donut legend. **Never use API data as a
  `ChartConfig` key**: shadcn's `ChartStyle` writes the keys raw into a `<style>` via
  `dangerouslySetInnerHTML`, and the API accepts any category text — key by position
  (`slice-0`…) and put the text in `label` (`CategoryDonut.test.tsx` guards this).
  `ChartTooltipRow` also takes a `marker` that replaces the square: `TrendChart` passes
  `LineIcon` (solid for both balances, dashed for income) so the tooltip repeats the legend's
  markers. `EdgeToEdgeCurve` is the `shape` of `TrendChart`'s lines — on a category axis
  recharts places each point at the centre of its band, and the shape stretches the curve to
  the plot edges via `usePlotArea`. Income is a constant `Line`, not a `ReferenceLine`: the
  recharts 3.8 `Legend` takes no `payload`, so only series reach the legend.
  **Axis label colour goes through the axis `tick={{ fill }}` prop**: shadcn's
  `[&_.recharts-cartesian-axis-tick_text]` selector does not match recharts 3.8 (the text is
  `.recharts-cartesian-axis-tick-value`), so labels fall back to recharts' fixed `#666` and a
  class on `ChartContainer` does nothing.
- **Tests** — `npm test` (vitest + jsdom, config in `vite.config.ts`). `shared/format.test.ts`
  covers the pure helpers; every screen and the shared components with behaviour (`Header`,
  `MonthNav`, `TrendChart`, `CategoryDonut`) have a `.test.tsx` beside them, rendering with
  `@testing-library/react` and mocking `@/data/api`. Mock fixtures are typed against
  `shared/types.ts`, so a fixture with a wrong field type fails `npm run build`. Those mocks are
  hand-written, so they do **not** catch a backend contract change — a field can disappear from
  `Summary` and the test stays green. The gap is wider than it looks for the OFX upload: the
  multipart request itself is never exercised here (vitest mocks `@/data/api`) nor in pytest
  (which runs no JavaScript), so that seam is only ever checked by hand.
- **`App.tsx`** — route table only (`/login`, `/`, `/lancamentos`, `/fatura`, `/importar`,
  `/configuracoes`), via `react-router`. `main.tsx` wraps the app in `BrowserRouter` +
  `AuthProvider`. Screens live one per file in `src/presentation/pages/` (`LoginScreen`,
  `SummaryScreen`, `EntryScreen`, `InvoiceScreen`, `ImportScreen`, `ConfigScreen`). A new screen
  also needs its tab in `Header.tsx` — the route alone leaves it unreachable. Navigate with
  `useNavigate()`, not `<Link>` — the shadcn `Button` (Base UI) has no confirmed support for
  rendering as another element (Radix's `asChild`).

### Money in the frontend

FastAPI serializes `Decimal` as a **string**, so every money field the API *returns* is typed
`string`; money the API *accepts* (`EntryCreate.amount`, `IncomeIn.amount`) is
`number | string`, because Pydantic parses either. Always `Number(value)` before arithmetic or
formatting, and send money back as the string the user typed, never a computed JS float — the
backend parses it into `Decimal` exactly.

### UI conventions

- **Tailwind CSS v4**, configured via the `@tailwindcss/vite` plugin. There is no
  `tailwind.config.js` — theme tokens are CSS variables in `src/index.css`.
- **shadcn/ui on Base UI, not Radix.** `@base-ui/react` is the primitive library. Most
  shadcn snippets found online assume Radix and will not work as-is. Icons come from
  `@remixicon/react`, not lucide.
- Style preset is `base-nova`, base color `neutral`, with `cssVariables: true`.
- **Check shadcn before building anything by hand.** Search the registry
  (`npx shadcn@latest search <termo>`, or the catalogue in `.agents/skills/shadcn/`) *before*
  writing a component yourself or reaching for another library. The theme already ships the
  tokens its components expect — semantic colours and `--chart-1..5` (plus our own
  `--chart-income`, amber, for the trend chart's income line, and `--chart-month-balance`,
  blue, for its month-balance line, until a new palette replaces them) — so anything
  hand-rolled
  falls outside that consistency. If shadcn has it and you still choose not to use it, say why.
  This rule fires **before** the decision, not after: it is what stops a hand-made bar chart
  from being written when `Chart` exists.
- **Installed so far**: `Button`, `Input`, `Label`, `Card`, `Table`, `Chart`, `Checkbox`,
  `Badge`, `Dialog`, `NativeSelect`, `Toggle`, `ToggleGroup`
  (`src/presentation/components/ui/`). `Chart` wraps recharts — that is why the charts are
  lazy-loaded (see the `presentation/components/` item above). Install more with the shadcn CLI
  (`npx shadcn@latest add <name>`) rather than writing them by hand.
- **Closed-choice fields**: category (in `EntryScreen` and on each `ImportScreen` line) is a
  `NativeSelect`, not the Base UI `Select` popup — a real `<select>` keeps the phone's native
  picker, the form's `required` and `selectOptions` in tests. Two-option choices (type, method,
  theme) are a `ToggleGroup` with a group label; `onValueChange` ignores the empty array a
  second click on the chosen item sends, so the field never ends up empty.
- **Local edits to shadcn files** — re-apply them if a component is reinstalled with
  `--overwrite`: `native-select.tsx` uses `text-base md:text-sm` like `Input` (shadcn ships
  `text-sm`, and below 16px iOS Safari zooms the page on focus); `toggle.tsx` styles the pressed
  item as filled `primary`, like `Button`'s default, instead of shadcn's faint `bg-muted`;
  `dialog.tsx` reads "Fechar" in the close button's `sr-only` text (shadcn ships "Close").
- Use the `@/` alias for every import inside `src/` (`@/presentation/components/ui/button`,
  `@/data/api`). `components.json` aliases point into `src/presentation/`, so the shadcn CLI
  writes new components there.
- Compose with `cn()` from the **`cn` package** (`import { cn } from 'cn'`), the official shadcn
  replacement for `clsx` + `tailwind-merge`. There is no `utils.ts` (the shadcn `lib` alias
  points to `src/shared/`) — do not create one.
- Colors come from the semantic tokens (`bg-background`, `text-foreground`, `border-border`,
  `text-destructive`), never hardcoded hex or raw palette classes — that's what keeps dark mode
  working.

## Reminders that apply here

- Never reimplement invoice, balance or installment math here — call the API.
- A backend schema change means regenerating `api-schema.d.ts` in the same commit
  (`docker compose restart api`, then `npm run gen:types`).
